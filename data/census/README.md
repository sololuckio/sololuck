# Solo Mining Census data

A copy of the open data behind [sololuck.io/census](https://sololuck.io/census): every Bitcoin
solo pool that publishes its numbers, read once an hour from each pool's own public endpoint and
frozen into weekly editions. How it is collected, and every formula, is documented at
[sololuck.io/census/method](https://sololuck.io/census/method).

We run one of these pools (SoloLuck). It is read and listed on the same terms as the others.

## Files

| Path | What it is |
|---|---|
| `editions/YYYY-Wnn.json` | One frozen weekly edition (ISO week, Monday 00:00 to Monday 00:00 UTC): weekly medians, coverage, sha256. Never edited. |
| `editions/YYYY-Wnn.csv` | The same edition as a flat table (columns below). |
| `editions/YYYY-Wnn-r2.json`, `.csv` | A correction. It names the edition it replaces in `supersedes`; the original stays in place, unchanged. |
| `latest.json` | The site's `current.json` as it stood at the last daily mirror run: the latest hourly reading of every pool. It changes daily and is not an edition. |

Files are copied by the `census-mirror` workflow in this repository, once a day. The workflow only
downloads the exports sololuck.io already publishes; it never contacts a mining pool.

## Edition CSV columns

One row per measured value.

| Column | Meaning |
|---|---|
| `edition` | Edition id, e.g. `2026-W38` or `2026-W38-r2` |
| `section` | `coverage`, `pool`, `not_published`, `ckpool_endpoint`, `device` or `headline` |
| `key` | Pool id, endpoint host, device name or headline field |
| `name` | Human-readable name |
| `metric` | What the value is, e.g. `miners_median`, `hashrate_median`, `average_median`, `chance_home_block_month` |
| `value` | The number (or text, for `fee` and `checked`) |
| `unit` | `H/s`, `count <field as the pool publishes it>`, `devices`, `difficulty`, `probability`, `hours` |
| `window` | The averaging window of a hashrate figure, as the pool publishes it |
| `hours` | How many hourly readings the value is the median of (out of 168) |

Things to know before reusing the numbers:

- **Miner counts are not comparable across pools and are never added up.** CKPool counts addresses
  (`Users`), Public Pool counts connected devices (`totalMiners`). The CSV names the field each count
  comes from in `unit`.
- **CKPool's endpoint rows are parts of the CKPool total**, not extra pools. Adding them to it counts
  the same miners twice. The evidence is on the method page.
- `chance_home_block_month` is `1 − exp(−(H_home ÷ H_net) × 4383)`, with `H_home` the combined hashrate
  of Public Pool's `bitaxe` and `NerdQAxe++` devices and `H_net = D × 2^32 ÷ 600` from SoloLuck's own
  Bitcoin node difficulty. It is a **lower bound**: home miners outside those two device names only
  add to it.
- Device names are shown exactly as miners report them to Public Pool (merged only where they differ
  by capital letters). It is Public Pool's population, not every solo miner.
- `sololuck_bitcoin_blocks_found` in `latest.json` is generated by the site from its own record of
  solved Bitcoin blocks.

## Verify a file

Each edition page on sololuck.io prints the sha256 of its JSON and CSV files as served, and the
edition JSON carries the CSV's sha256 in `csv_sha256`:

```sh
sha256sum data/census/editions/2026-W38.json data/census/editions/2026-W38.csv
```
